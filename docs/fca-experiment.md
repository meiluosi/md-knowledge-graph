# 实验：从数据推导规则（FCA）

## 为什么做这个实验

项目的定位曾被批评为站不住：**"结构还对不对"由维护者说了算，工具凭什么判？**

按"是否需要人定标准"拆开 11 条检查项后，结论是：

```
客观的那半（引用完整性）  ×  与 lychee 重叠
独有的那半（标签健康度）  ×  是我发明的意见
独有 ∩ 客观 = ∅
```

于是提出第三条路：**规则不从工具来，也不从人来，而是从数据里推出来。**

形式概念分析（FCA）天然匹配标签数据：把「文章 × 标签」看作形式背景，就能推导**蕴含**——`{QLoRA} → {微调}` 成立，当且仅当所有带 `QLoRA` 的文章都带 `微调`。

这不是谁的意见，是从语料里读出来的事实。

**本文是这个想法的验证结果。结论是负面的。**

## 实验设置

| | |
|---|---|
| 语料 | 真实技术博客，33 篇 / 19,673 行（从 git HEAD 导出） |
| 形式背景 | 33 个对象 × 26 个属性（标签 15 + 分类 9 + 年份 2） |
| 前件大小 | 1 与 2（枚举全部组合） |
| 支持度阈值 | ≥ 2，另测 ≥ 4 |

## 结果

### 1. 退化属性污染了大部分结论

```
year:2024  32 篇
year:2026   1 篇
```

13 条精确蕴含里有 **11 条含 `year:2024`**——因为年份几乎是常数，被"推导"进了几乎所有规则。

```
tag:因果推断   →  year:2024     (支持 9)
tag:强化学习   →  year:2024     (支持 9)
cat:Data Science → year:2024    (支持 6)
…
```

**FCA 没有"这个属性没有信息量"的概念。** 它会一本正经地产出这 11 条垃圾。

> 任何"自动发现规则"的方法都需要一个信息量过滤器，否则噪声会淹没一切。

### 2. 剔除年份后，只剩同一个形状

```
cat:Reinforcement Learning  →  tag:强化学习        (支持 5)
cat:Research                →  tag:因果推断        (支持 5)
tag:数据处理                →  cat:Data Science    (支持 4)
tag:模型架构                →  cat:Deep Learning   (支持 3)
cat:NLP                     →  tag:Agent与RAG      (支持 2)
tag:后训练(RLHF/DPO)        →  cat:Deep Learning   (支持 2)
```

全部是 **分类 ⊆ 标签**。含义是：**分类没有提供标签之外的信息。**

但这**很可能正是作者有意的设计**——标签 =「提到过」，分类 =「主题就是它」。若是如此，工具发现的是作者**早已知道的事**。

### 3. 时间漂移检出的东西没有统计意义

把语料按日期对半切，找"前半段 100% 成立、后半段被打破"的蕴含：

```
cat:Data Science  → tag:数据处理    前半 2 篇全中，后半 50%  (4 篇)
cat:Game AI       → tag:游戏AI与搜索 前半 2 篇全中，后半 50%  (2 篇)
tag:Agent与RAG    → cat:NLP         前半 2 篇全中，后半 0%   (1 篇)
```

**靠 2 篇建立规则、再靠 4 篇推翻它——这是噪声，不是信号。**

能稳定成立的只剩 2 条，且都是「标签 ↔ 分类」的同义关系。

## 根因

| 根因 | 具体 |
|---|---|
| **对象太少** | 33 篇。支持度 4–5 意味着规则建立在 **4–5 个数据点**上。任何归纳方法在这个规模上都只能产出噪声 |
| **属性不成体系** | 26 个属性里年份近乎常数；标签与分类是作者手工设计的，彼此高度共线 |
| **没有真正的「约定」可违反** | 作者只有直觉，没有一套会被违反的成文规矩 |

## 一个反直觉的方法论结论

「从数据推规则」需要的前提是：**对象之间存在「本应一致、却可能不一致」的重复模式。**

- 手工维护的小语料里，**每条记录都是独特的**，不存在可归纳的规律
- 恰恰只有**大到人力无法全览**的语料才有规律可循

于是出现一个闭环：

> **需要它的地方**（几千文件、多人协作、跨年演进），通常已经有更直接的手段——schema、lint 配置、代码生成。
> **没有那些手段的地方**（个人博客），它又推不出任何东西。

## 这个实验证明了什么

1. **验证了那个批评是对的。** 独有 ∩ 客观确实为空集——试图用"数据推导"填这个空集，填不上。
2. **一个下午的实验胜过一个 FCA 库。** 如果先写了实现再验证，代价会大得多。
3. **项目自己的原则又生效了一次**：*越是吻合自己想讲的故事，越要查。*

第 3 条值得单独记：上一轮我对这个方向是偏乐观的——"数学真正能帮上忙的地方"这种说法本身就带着期待。**这次的幸运之处在于，验证成本低到可以先测再做。** 如果验证成本很高，我大概会直接开始写，然后在这个方向上投入几周才发现它推不出东西。

## 结论

**这条路线不成立。** 不是实现不够好，而是**前提在目标场景里不成立**——语料的规模和形态不支持"从数据推规律"。

按已定的冻结规则：**停止，不再为它加功能。** 把定位改诚实，作为个人工具收尾。
