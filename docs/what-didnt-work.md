# 踩过的坑

这份文档记录 md-knowledge-graph 开发过程中**实际踩过**的坑和实测数据。
README 只留摘要，细节在这里。

写作原则：只写真实发生过的。有测试的贴测试，有数据的贴数据。

---

## 1. 手写 frontmatter 解析器会静默丢数据

本工具的前身是一个 51 行的、零依赖的手写 YAML 子集解析器。

逻辑是：遇到 `key:` 空值就进入数组模式，逐行收 `- ` 项；只有 `title` / `category` 被当作标量处理。

它在我自己的 33 篇文章上**从未出错**——因为那些文章恰好全用了块式数组。换几种同样合法的写法，实测结果：

| frontmatter 写法 | 手写解析器结果 | |
|---|---|---|
| `tags:\n  - A\n  - B` | `["A", "B"]` | ✅ |
| `tags: [A, B]` | `[]` | ❌ **静默丢数据** |
| `tags: A` | `[]` | ❌ **静默丢数据** |
| `title: "X: Y"` | `"X: Y"` | ✅ |

问题不在实现粗糙，而在**缺陷形态**：

> 它对非法输入不报错，对合法输入也照样返回空数组。

使用者拿到的是一张少了文章、却不报任何错的图。这类"静默数据丢失"是数据工具最不该有的缺陷。

**所以本项目引入了唯一的依赖 `gray-matter`。** 不是偷懒——是承认「自己维护一个 YAML 子集」的边界成本远高于一个成熟依赖。

上面三种写法现在是三条回归测试（`test/graph.test.js` 的 `normalizeList` 组）。

## 2. 同一概念的两种写法会产出「畸形图」，不是「多一个节点」

实现标签节点时按原写法直接建节点，于是 `PEFT` 和 `peft` 产生了**两个 id 完全相同、label 不同的节点**：

```
tag:peft("PEFT")
tag:peft("peft")     ← 同一个 id 出现两次
```

这不是"图上多一个点"那么轻——它破坏了图的完整性：

- Mermaid 里是重复定义
- 前端按 id 建索引会**互相覆盖**
- 下游拿到的边指向哪个节点，取决于遍历顺序

修复方式是按 slug 归并（`aggregateBySlug`）：

- 计数口径改为「多少篇文章用了这个概念」，同一篇里写两种拼写只算一次
- 规范写法按**多数决**选出
- 票数并列时优先大写更多的那个（`PEFT` 优于 `peft`）

回归测试在 `test/graph.test.js` 的「同概念不同写法的归并」组。

### 附带教训：检查和出图必须共用同一套归并逻辑

最初检查器按原写法统计，于是它**一边警告"会被合并成同一个节点"，一边又按两种拼写各报了一次**——警告本身是错的。

工具内部两处对同一概念有两种口径，是比 bug 更麻烦的问题：它让用户没法信任任何一处输出。

## 3. 代码块里的示例链接会被当成真断链

技术文章里经常出现这种内容：

````markdown
参考 [示例](not-a-real-post.md) 的写法
````

第一版直接对全文做正则，于是所有**文档示例**都成了断链，一篇文章能报出十几条假错误。

现在解析前会剥掉围栏代码块、波浪号代码块、行内代码和 HTML 注释（`stripCode`），只解析真正的正文链接。

验证方式是在示例语料里**故意放一个假链接**：

```
$ mdkg --posts examples --check
✗ 正文断链 —— 1 项
    2026-01-08-qlora-4bit → ./2026-01-01-deleted-draft.md
```

只报出一条——代码块里的 `not-a-real-post.md` 和行内代码里的 `also-fake.md` 都没有被误报。

## 4. wikilink 曾经永远连不上

`resolveTarget` 最初只做路径解析：

```js
path.join(path.dirname(from.id), target)
```

这对 `./a.md` 有效，但 `[[thing]]` 这种不带路径的目标**永远解析不出结果**。

也就是说：功能看起来实现了，测试也"通过"了（因为没有测试覆盖它），**实际一条边都没产生**。

修复时加了一层"无斜杠目标按文件名查找"的回退，但有一个有意的限制：

> 这层回退**只对不含 `/` 的目标启用**。

否则 `./gone.md` 会因为别处恰好有个 `gone` 而被误判成有效链接，**把真正的断链掩盖掉**——这是检查器最不该做的事。

宁可漏报（判为断链）也不能误报（把断链说成好的）。

## 5. 我的测试断言写错过两次，而且两次都该先怀疑测试

**第一次**（`buildGraph`）：我断言"有分类但标签全被过滤的文章仍应入图"。

```
✖ 有分类但标签全被过滤的文章仍然入图
  AssertionError: 文章 c 应通过分类连入图
```

但我构造的数据里那篇文章的 `category` 是空字符串——它本来就该被排除。**是断言错了，不是代码错了。**

**第二次**（`computeRelated`）：`minScore: 3` 时分数恰好是 3，阈值是闭区间、应该保留，我却断言成排除。

两次都差点让我去改一个本来正确的实现。所以：

> **测试失败时，先怀疑测试。**

## 6. 一个拼写事故：`Set.set` 不是 `Set.add`

写标签大小写检查时用了：

```js
bySlug.get(key).set(name);   // Set 没有 set 方法
```

冒烟测试立刻炸了：

```
错误：bySlug.get(...).set is not a function
```

教训很小但很实际：**第一版跑起来看一眼，比读三遍代码便宜。**

补充一句：这个 bug 单元测试当时抓不到——因为那部分测试还没写。是"跑一下看看"抓到的。

## 7. 生成物也需要被测试

`--format html` 的输出是 HTML。**语法正确不代表能跑。**

一个 NaN 坐标、一个漏掉的 canvas 方法，用户拿到的就是一张白屏，而只做语法检查的 CI 抓不到。

`test/html-runtime.test.js` 因此搭了一个最小 DOM stub，把内嵌脚本**真正执行一遍**，断言：

- 每个节点都被绘制（`arc` 调用次数 == 节点数）
- 所有坐标都是有限值（没有 NaN / Infinity）
- 画布按 DPR 正确放大

`test/cli.test.js` 同理。**退出码是 CI 唯一真正依赖的契约**——单元测试全绿但退出码错了，CI 依然是坏的。所以以子进程方式真正把命令跑起来，断言退出码与输出。

## 8. 一个函数被两处复用，产生了整类误报

提取标题锚点时，我直接复用了为**链接提取**写的 `stripCode`。它的行为是「把代码块和行内代码**内容整段删掉**」。

对链接这是对的：

```markdown
参考 [示例](not-a-real-post.md) 的写法     ← 代码块里的假链接，必须删掉
```

但对标题这是错的：

```markdown
## Use `foo` here
```

GitHub 渲染这个标题得到文字 `Use foo here`，锚点是 **`use-foo-here`**。而行内代码被整段删掉后，我的实现算出的是 **`use-here`**。

后果不是"少报"，而是**把正确链接报成失效锚点**——每一篇标题里带行内代码的文档都会炸。

### 这是怎么被发现的

不是我读代码看出来的，是写测试时对照 `github-slugger` 的**实际输出**发现的：

```
✖ "## Use `foo` here" → use-foo-here
```

我把期望值定成 `use-foo-here`（因为那是渲染器的真实行为），实现给出 `use-here`，测试立刻红了。

**这条说明为什么"参考实现的实测输出"比"我以为的规则"更值得当期望值写进测试。**

### 修法

拆成两个语义不同的函数，并在模块文档里写清什么时候用哪个：

| 场景 | 函数 | 行为 |
|---|---|---|
| 提取链接 | `stripCode` | 行内代码**连内容**一起去掉 |
| 提取标题 | `unwrapInlineCode` | 只去反引号，**保留内容** |

教训：**一个"没错"的工具函数被复用到语义不同的场景，本身就能制造整类误报。** 名字里带 `strip` 的函数，复用时要想清楚"剥掉的东西是不是对方需要的"。
